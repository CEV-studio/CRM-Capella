Date : 2026-07-25
Statut : validé par Jeremy, prêt pour le plan d'implémentation.

Ce lot fait suite aux étapes 1–6 (CRM complet en ligne sur `crm.capellaenergy.fr`).
La base de production est **encore vide** (migration Sheets non faite) : c'est
le bon moment pour changer la forme des données sans risque de migration.

## Périmètre

Cinq changements, livrés ensemble via une nouvelle migration SQL (`0004`) et les
écrans associés.

1. Champs leads : `puissance` → `car_electricite` + `car_gaz` (MWh).
2. `nom_prenom` → `nom` + `prenom` (prospects et affaires).
3. Suppression douce (corbeille récupérable) des prospects et affaires, admin.
4. Permissions par personne : `can_export`, `can_view_all`, `can_manage_team`.
5. Pièces jointes ACD / Facture (Supabase Storage), multiples, par prospect,
   remontées sur l'affaire liée.

## 1. Champs CAR (remplace Puissance)

**Base** (`prospects`) : supprimer `puissance` ; ajouter
`car_electricite numeric(12,3)` et `car_gaz numeric(12,3)` (MWh).

**UI** : fiche prospect (bloc Énergie) — deux champs numériques à virgule
française tolérée. Retirer « Puissance ».

**Import** : template — colonne « Puissance » remplacée par « CAR Électricité »
et « CAR Gaz ». `COLONNES_IMPORT` et l'exemple mis à jour. Valeurs lues comme
nombres (virgule → point).

**Affaires** : conservent `car_mwh` tel quel (hors périmètre — pas de demande).

## 2. Nom / Prénom séparés

**Base** : `prospects` et `affaires` — supprimer `nom_prenom` ; ajouter
`nom text` et `prenom text`.

**UI** : fiches prospect et affaire — deux champs « Nom » et « Prénom ».
Listes/cartes : afficher `prenom + " " + nom` (helper `nomComplet()`), en
retombant sur la raison sociale si les deux sont vides.

**Bascule prospect → affaire** : recopier `nom` et `prenom` séparément
(actions `convertirProspect` et pré-remplissage `nouvelle`).

**Import** : colonne « Nom Prénom » → deux colonnes « Nom » et « Prénom ».

**Recherche prospection** : le `.or(...)` cherche désormais sur `nom` et
`prenom` (au lieu de `nom_prenom`).

## 3. Suppression avec corbeille (soft delete)

**Base** : ajouter `deleted_at timestamptz` sur `prospects` et `affaires`.
Une ligne « supprimée » a `deleted_at` non nul.

**Lecture** : toutes les listes et fiches existantes filtrent
`deleted_at is null`. Les compteurs KPI, commissions, réservoir, pipeline aussi.

**RLS** : inchangée sur le fond ; l'admin (et `can_manage_team`) voit les
lignes supprimées uniquement dans l'écran Corbeille (requête explicite
`deleted_at is not null`).

**Actions (admin uniquement, via clé de service après `requireManageTeam`)** :
- `mettreALaCorbeille(type, id)` : pose `deleted_at = now()`.
- `restaurer(type, id)` : remet `deleted_at = null`.
- `supprimerDefinitivement(type, id)` : `delete` réel (et supprime les pièces
  jointes liées + fichiers Storage).

**UI** :
- Bouton « Supprimer » (discret, avec confirmation) sur les fiches prospect et
  affaire — visible seulement pour l'admin / `can_manage_team`.
- Nouvel écran `/admin/corbeille` : deux onglets (prospects, affaires),
  boutons Restaurer / Supprimer définitivement. Entrée de menu Administration.

**Décision** : la suppression n'est PAS donnée aux commerciaux (interrupteur
non retenu). Seuls admin / `can_manage_team` suppriment.

## 4. Permissions par personne

**Modèle** : trois colonnes booléennes sur `profiles`, défaut `false` :
- `can_export` — accès à l'export CSV.
- `can_view_all` — voit prospects/affaires de toute l'équipe.
- `can_manage_team` — équivalent admin fonctionnel (créer comptes, réservoir,
  attribution, commissions de tous, corbeille).

L'admin historique (`role = 'admin'`) garde tout, indépendamment de ces
drapeaux. On introduit des fonctions SECURITY DEFINER :
- `can_view_all()` = `is_admin() OR (profiles.can_view_all du user courant)`.
- `can_manage()` = `is_admin() OR can_manage_team du user courant`.

**RLS étendue** :
- `prospects` / `affaires` SELECT : `own OR can_view_all()`. (UPDATE/INSERT
  restent « own » ; `can_manage()` conserve le plein accès admin.)
- Les policies « admin_all » deviennent basées sur `can_manage()`.

**Auto-octroi impossible** : le trigger `tg_protect_profile_privileges` est
étendu pour figer aussi `can_export`, `can_view_all`, `can_manage_team` pour un
non-admin. Seuls admin / `can_manage()` peuvent les changer.

**UI** : écran Commerciaux — trois cases à cocher par ligne, sauvegarde
immédiate (server action `modifierPermissions`, protégée par `requireManage`).
Étiquette d'avertissement sur « Voir tous les leads » et « Gérer l'équipe ».

**Garde-fous serveur** :
- `requireAdmin()` reste pour les opérations strictement réservées au fondateur.
- Nouveau `requireManage()` (admin OU `can_manage_team`) pour créer des comptes,
  attribuer, corbeille.
- Nouveau `requireExport()` (admin OU `can_export`) pour la route d'export.
- Les écrans « admin only » de l'app-shell s'affichent si `can_manage()`.

## 5. Pièces jointes ACD / Facture

**Stockage** : bucket Supabase Storage **privé** `pieces-jointes`. Chemin :
`prospects/{prospect_id}/{uuid}-{nom}` ou `affaires/{affaire_id}/{uuid}-{nom}`.

**Base** : table `pieces_jointes` :
- `id uuid pk`, `type text check (type in ('ACD','Facture'))`,
- `prospect_id uuid null references prospects`, `affaire_id uuid null references affaires`
  (contrainte : au moins l'un des deux non nul),
- `bucket_path text`, `file_name text`, `mime text`, `taille int`,
- `uploaded_by uuid`, `created_at`.

**Suppression des cases texte** : retirer l'usage UI de `affaires.acd` et
`affaires.facture` (les colonnes peuvent rester en base, non affichées, pour ne
rien casser ; l'export les ignore au profit des pièces jointes).

**Fiche prospect** : deux sections « ACD » et « Facture ». Chaque section :
liste des fichiers (nom, taille, lien de téléchargement, bouton supprimer) +
bouton d'ajout. Upload via server action + Storage.

**Fiche affaire** : mêmes deux sections, montrant :
- les pièces jointes de l'affaire (`affaire_id`),
- **plus** celles du prospect d'origine (`prospect_id` = `affaire.prospect_id`),
  en lecture (badge « du prospect »).
Ajout direct possible (rattaché à l'affaire).

**Contraintes fichier** : MIME dans {application/pdf, image/jpeg, image/png},
taille ≤ 10 Mo. Vérifiées côté serveur avant upload.

**Sécurité (le point critique)** : RLS sur `pieces_jointes` ET policies sur
`storage.objects` du bucket :
- SELECT/INSERT/DELETE autorisés si l'utilisateur possède le prospect/affaire
  lié (via jointure), ou `can_view_all()` (lecture) / `can_manage()`.
- Le bucket est privé : les fichiers ne sont accessibles que par URL signée
  générée côté serveur après vérification du droit. Jamais d'URL publique.
- Suppression définitive d'un lead (corbeille) → supprime les objets Storage.

**Téléchargement** : route serveur `/api/piece/{id}` qui vérifie le droit puis
renvoie une URL signée courte (ou stream le fichier). Pas de lien public direct.
